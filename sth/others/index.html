各种随手小记

cofusion matrix （混淆矩阵）

在分类任务中，模型对每个输入都会给出一个预测类别，但预测结果和真实标签之间并不会完全一致。为了系统记录这些“对应关系”，就需要一个结构，把 真实是什么 和 模型认为是什么 逐一统计下来，这个结构就是混淆矩阵

设有一个分类问题，类别集合为

\[ \mathcal{Y} = \{1,2,\dots,K\} \]

数据集中每个样本都有真实标签 \(y\)，模型输出预测标签 \(\hat{y}\)。混淆矩阵本质上是一个 \(K \times K\) 的计数矩阵 \(M\)，其中每个元素定义为：

\[ M_{ij} = \#\{x \mid y=i,\ \hat{y}=j\} \]

也就是说，矩阵的第 \(i\) 行第 \(j\) 列表示：真实属于第 \(i\) 类，但被预测为第 \(j\) 类的样本数量。这样一来，对角线 \(M_{ii}\) 就是预测正确的部分，而所有非对角线元素都对应不同形式的“混淆”。

如果把问题限制到二分类（例如安全场景中的“正常 / 攻击”），这个矩阵会变成一个 2×2 的结构，此时每个位置都有明确语义：

  • 真正例（True Positive, TP）：真实是攻击，预测也是攻击
  • 假正例（False Positive, FP）：真实是正常，被误判为攻击（误报）
  • 假负例（False Negative, FN）：真实是攻击，但没有识别出来（漏报）
  • 真负例（True Negative, TN）：真实是正常，预测也正常

这些量之间的关系并不是孤立的，它们直接决定了常用评估指标。

精确率（Precision）关注的是“被判为攻击的样本里有多少是真的攻击”：

\[ \text{Precision} = \frac{TP}{TP + FP} \]

召回率（Recall） 关注的是“所有真实攻击中有多少被识别出来”：

\[ \text{Recall} = \frac{TP}{TP + FN} \]

F1 值 则是在这两者之间做一个平衡：

\[ F1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} \]

把这些关系放回你在做的 LLM Firewall 或攻击检测场景，可以看到混淆矩阵不是一个展示工具，而是调参和定位问题的核心依据。

比如：

  • 当 FP 较高时，说明模型把正常请求误当成攻击，通常对应规则过严或阈值过低；
  • 当 FN 较高时，说明模型漏掉了攻击，可能是特征表达不足，或者攻击样本分布没有被覆盖。

PR curve （PR 曲线）

在分类模型的输出中，如果模型给出的不是一个离散标签，而是一个连续的“置信度分数” \(s(x)\in[0,1]\)，那么最终的分类结果就取决于阈值 \(\tau\)：当 \(s(x)\ge \tau\) 时判为正类，否则为负类。阈值一旦改变，前面提到的 \(TP, FP, FN\) 都会随之变化，于是精确率和召回率也会发生联动变化。PR 曲线就是把这种“随阈值变化的关系”系统地展开出来。

先固定符号。设数据集中正类样本集合为 \(\mathcal{P}\)，负类为 \(\mathcal{N}\)。在某一个阈值 \(\tau\) 下，可以得到一组 \((TP(\tau), FP(\tau), FN(\tau))\)，从而计算：

\[ \text{Precision}(\tau) = \frac{TP(\tau)}{TP(\tau)+FP(\tau)}, \quad \text{Recall}(\tau) = \frac{TP(\tau)}{TP(\tau)+FN(\tau)} \]

当 \(\tau\) 从 1 逐渐降低到 0 时，模型会越来越“宽松”，更多样本被判为正类。这个过程中，

  • Recall 会单调增加，因为被找出的正样本越来越多；

  • 同时 Precision 往往会下降，因为被判为正类的集合中混入了更多负样本。

把每一个阈值对应的一对 \((\text{Recall}, \text{Precision})\) 作为平面上的一个点，就得到一条曲线，这就是 PR curve。

\[ y = P(R) \]

这里可以把 Precision 看作 Recall 的函数关系（实际由阈值隐式决定），曲线整体描述的是：在不同召回水平下，模型能够维持怎样的精确程度。

为了进一步量化这条曲线，通常会计算曲线下的面积，即 Average Precision（AP）。离散情况下，可以写成对 Recall 分段的加权求和：

\[ AP = \sum_{k} \big(R_k - R_{k-1}\big)\, P_k \]

其中 \(R_k\) 是第 \(k\) 个阈值对应的召回率，\(P_k\) 是对应的精确率。这一指标本质上在回答：当逐步放宽判定标准、覆盖更多正样本时，模型整体维持了多高的“纯度”。

把它放到安全检测或 LLM Firewall 场景中，可以看到 PR 曲线直接对应策略调节问题。

  • 阈值较高时，只拦截置信度很高的攻击，请求通过率高，但会漏掉一部分攻击（Recall 低）；

  • 阈值降低后，可以覆盖更多攻击（Recall 提升），但误报开始增加（Precision 下降）。

PR 曲线把这种权衡关系完整展开，使你可以根据业务约束选择一个工作点，例如在可接受的误报水平下尽可能提高攻击覆盖率。

当数据分布高度不平衡（例如攻击样本远少于正常流量）时，PR 曲线比 ROC 曲线更敏感，因为 Precision 直接依赖于 FP 的数量变化，而 FP 在大规模正常流量中会迅速放大对系统的影响。这也是为什么在安全检测任务中，PR 曲线通常比 ROC 更有解释力。

ROC

当模型输出的是一个连续分数 \(s(x)\) 时，分类结果依赖阈值 \(\tau\)。随着阈值变化，模型对“正类/负类”的判定边界会移动，从而改变 \(TP, FP, TN, FN\) 的数量。ROC 曲线就是把这种变化过程转化为一个稳定的几何结构。

先明确两个核心量。对任意阈值 \(\tau\)，定义：

\[ \text{TPR}(\tau)=\frac{TP(\tau)}{TP(\tau)+FN(\tau)}, \quad \text{FPR}(\tau)=\frac{FP(\tau)}{FP(\tau)+TN(\tau)} \]

  • TPR（True Positive Rate）描述的是：所有真实正类中，被识别出来的比例；

  • FPR（False Positive Rate）描述的是：所有真实负类中，被误判为正类的比例。

ROC 曲线把每一个阈值对应的一对 \((\text{FPR}, \text{TPR})\) 映射到平面上，形成一条从 \((0,0)\) 到 \((1,1)\) 的曲线。

\[ y = TPR(FPR) \]

从阈值变化的角度看，\(\tau\) 很高时，模型几乎不判正类，此时 \(TPR \approx 0\)，\(FPR \approx 0\)，点位在左下角；随着 \(\tau\) 下降，模型逐渐放宽，更多样本被判为正类，\(TPR\) 上升，同时 \(FPR\) 也会上升，曲线向右上移动；当 \(\tau\) 极低时，几乎所有样本都被判为正类，对应点接近 \((1,1)\)。

这条曲线的形状反映了模型的“区分能力”。如果模型完全没有区分能力，相当于随机猜测，那么不同阈值下得到的点会接近对角线 \(y=x\)。如果模型能够把正负样本分开，曲线会向左上方凸起，在较低的 FPR 下就能获得较高的 TPR。

为了把整条曲线压缩成一个数，通常计算 AUC（Area Under Curve）：

\[ AUC = \int_0^1 TPR(FPR)\, dFPR \]

这个值可以理解为：随机抽取一个正样本和一个负样本，模型把正样本评分排在负样本之前的概率。AUC 越接近 1，说明排序能力越强。

回到安全检测或 LLM Firewall 场景，ROC 曲线对应的是这样一个过程：随着阈值降低，系统会拦截更多请求，其中既包括真实攻击（提升 TPR），也包括误判的正常请求（提升 FPR）。ROC 曲线展示的是“在不同误判水平下，攻击识别能力能达到什么程度”。

但这里有一个关键点：FPR 的分母是所有负样本数量。在实际流量中，正常请求往往远多于攻击请求，因此即使 FPR 很小，绝对的误报数量也可能很大。正是因为这个原因，在强不平衡数据（典型如攻击检测）中，ROC 曲线往往显得“过于乐观”，而前面提到的 PR 曲线会更直接反映误报对系统的实际影响。

threshold trade-off

当模型输出的是连续分数 \(s(x)\) 时，阈值 \(\tau\) 实际上定义了一条决策边界：

\[ \hat{y} = \mathbf{1}[s(x)\ge \tau] \]

这个边界一旦移动，所有统计量都会联动变化，因此“threshold trade-off”本质上是：在不同类型错误之间如何分配容忍度。

先把变化机制理清楚。将阈值从高逐步降低，相当于扩大“判为正类”的区域。这样会带来两个方向的变化：

一方面，原本被漏掉的正样本会逐渐被纳入，因此

\[ TP \uparrow,\quad FN \downarrow \]

召回率 \(\text{Recall} = \frac{TP}{TP+FN}\) 上升。

另一方面，一些负样本也会被错误纳入，因此

\[ FP \uparrow,\quad TN \downarrow \]

精确率 \(\text{Precision} = \frac{TP}{TP+FP}\) 通常下降，同时 FPR 上升。

这就形成一个不可同时优化的关系：提高覆盖能力（Recall 或 TPR），必然引入更多误判（FP 或 FPR）。阈值的作用就是在这两个方向之间选择一个平衡点。

如果把问题写成一个简单的决策优化形式，可以引入不同错误的代价。设误报的代价为 \(C_{FP}\)，漏报的代价为 \(C_{FN}\)，则期望风险为：

\[ \mathcal{R}(\tau) = C_{FP}\cdot FP(\tau) + C_{FN}\cdot FN(\tau) \]

阈值选择的过程就是在所有 \(\tau\) 中找到使 \(\mathcal{R}(\tau)\) 最小的点。这一步把“经验调参”转化为一个明确的优化目标。

放到安全检测或 LLM Firewall 场景，这个 trade-off 会更具体：

当阈值设置较高时，系统只拦截置信度很高的攻击，请求通过率较高，但会漏掉一部分攻击行为，这对应 FN 偏大；当阈值降低后，可以覆盖更多攻击，但误报开始增加，正常请求被拦截的比例上升，对应 FP 增大。

实际选择时，关键不在于曲线本身，而在于业务约束如何转化为代价结构。例如：

如果系统用于强安全边界（如敏感操作防护），漏掉攻击的代价远高于误报，那么应选择一个 Recall 较高的区域，即允许一定误报；如果系统面向用户体验（如内容审核前置过滤），误报会直接影响正常用户，则需要控制 FP，在 Precision 较高的区域选择阈值。

进一步，在真实流量中还要考虑类别不平衡。设正常请求数量远大于攻击请求，即 \(|\mathcal{N}| \gg |\mathcal{P}|\)，那么即使 FPR 很小，绝对误报数量 \(FP = FPR \cdot |\mathcal{N}|\) 仍然可能很大。这会使阈值选择偏向更保守的区域，或者需要引入分层策略（例如先高召回粗筛，再精排）。

因此，“threshold trade-off”并不是一个抽象概念，而是一个由分数分布、错误代价、数据比例共同决定的决策问题。阈值只是控制这个系统行为的一个参数，而真正决定取值的，是你希望系统在“漏掉攻击”和“误伤正常”之间承担哪一类风险。
